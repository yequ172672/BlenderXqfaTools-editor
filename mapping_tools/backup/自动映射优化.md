自动骨骼映射算法优化方案
目标文件: mapping_tools/modtoolkit.py
核心函数: auto_match_bones() 及其依赖的评分函数（L490-L551）
设计哲学: 预设驱动优先，用得越多越聪明，预设权重 0.45 和贪心匹配策略保持不变

优化 1: camelCase 和数字分词
问题: _tokenize() 只按 _, ., , - 分割，导致 camelCase 命名（如 "LeftArm"）无法拆分为 ["left", "arm"]，与 "left_arm" 的 Jaccard 相似度几乎为零。同理 "Finger01" 无法拆出数字部分。

修改 _tokenize()，在分词前对大写字母和数字段插入分隔符：

def _tokenize(name: str) -> list:
    name = re.sub(r'([A-Z])', r'_\1', name)
    name = re.sub(r'(\d+)', r'_\1', name)
    return [t for t in re.split(r"[_. \-]", name.lower()) if t]
效果: "LeftArm" → ["left", "arm"]；"Finger01" → ["finger", "01"]；"IndexFinger1_L" → ["index", "finger", "1", "l"]。无预设时名称匹配率显著提升。

注意: 该改动会把 "Bip001" 拆成 ["bip", "001"]，在部分配对中会引入 "bip"/"001" 等噪声 token，但整体收益大于代价。对于 "UpperArm" vs "upperarm" 这类全小写粘连命名，仅靠 token 级 Jaccard 仍无法匹配；若项目里这类命名普遍，需要额外引入 LCS 或编辑距离作为 name_score 的第三组分，不在本次范围内。

测试: 确保以下配对的 name_score 提升：
"LeftArm" vs "left_arm" → > 0.5
"Finger01" vs "finger_01" → > 0.5
"IndexFinger1_L" vs "index_finger_1_l" → > 0.5

优化 2: 侧别归一化
问题: _strip_side() 只处理前缀（L_, R_, left_, right_ 等），但大量骨骼命名使用后缀："Arm_L", "Hand.R", "finger1L"。这些侧别信息需要被统一归一化，否则 name_score 的 side bonus 无法正确比较。

实现: 扩展 _strip_side() 同时处理前缀和后缀，按长度降序匹配，避免短标记误删长标记。在 name_score() 中先对完整骨骼名归一化、再分词、再对单个 token 做一次侧别剥离，以同时覆盖：
- 整名前/后缀侧别：Arm_L, Hand.R, left_arm
- 中间 token 侧别：Bip001-L-Finger01
- 驼峰/数字拆分后暴露的裸侧别 token：finger1L

_SIDE_PREFIXES = [
    "left_", "right_", "l_", "r_",
    "left", "right",
    "lt_", "rt_", "lt", "rt",
]

_SIDE_SUFFIXES = [
    "_left", "_right", ".left", ".right",
    "_l", "_r", ".l", ".r",
]

def _strip_side(name: str) -> str:
    lower = name.lower()
    for prefix in sorted(_SIDE_PREFIXES, key=len, reverse=True):
        if lower.startswith(prefix):
            return lower[len(prefix):]
    for suffix in sorted(_SIDE_SUFFIXES, key=len, reverse=True):
        if lower.endswith(suffix):
            return lower[:-len(suffix)]
    return lower

name_score() 中的 side-stripped bonus 同步改造，并过滤空 token：

def name_score(name_a: str, name_b: str) -> float:
    tokens_a = set(_tokenize(name_a))
    tokens_b = set(_tokenize(name_b))
    if not tokens_a or not tokens_b:
        return 0.0
    intersection = tokens_a & tokens_b
    union = tokens_a | tokens_b
    jaccard = len(intersection) / len(union) if union else 0.0

    # 先整名归一化侧别，再分词，再对 token 做一次剥离，过滤空串
    stripped_a = {
        s for t in _tokenize(_strip_side(name_a))
        for s in (_strip_side(t),) if s
    }
    stripped_b = {
        s for t in _tokenize(_strip_side(name_b))
        for s in (_strip_side(t),) if s
    }
    if stripped_a and stripped_b:
        s_inter = stripped_a & stripped_b
        s_union = stripped_a | stripped_b
        side_bonus = len(s_inter) / len(s_union) if s_union else 0.0
    else:
        side_bonus = 0.0

    return jaccard * 0.7 + side_bonus * 0.3

注意: 不匹配裸 "l"/"r" 后缀（如把 heel 误删成 hee），侧别标记必须通过分隔符或驼峰/数字拆分成为独立 token 后才能被识别。

测试:
_strip_side("Arm_L") → "arm"
_strip_side("Hand.R") → "hand"
name_score("Arm_L", "arm_l") → > 0.5
name_score("Hand.R", "hand_r") → > 0.5
name_score("Bip001-L-Finger01", "Bip001-R-Finger01") 的 side_bonus 应接近 1.0（归一化后只剩非侧别 token 相同）

优化 3: 降低预设部分匹配分数
问题: preset_bonus() 中，仅 src 或 tgt 名字在任意预设条目中出现过（哪怕完全不相关的映射对），就给 0.10 或 0.25 分。在 0.45 权重下，0.10 × 0.45 = 0.045，0.25 × 0.45 = 0.1125，已经接近或超过 0.25 的匹配阈值。大量"噪声"配对会通过阈值，增加用户微调负担。

修改为:

if src_as_vg > 0 and tgt_as_bone > 0:
    return 0.10   # 两端都 Known，弱信号
return 0.0        # 只有一端 Known，不加分
理由: 误匹配比无匹配更危险。无匹配只是没自动填入，用户可以手动配对；误匹配则需要用户逐条检查纠正，反而增加工作量。仅双侧已知时给微弱提示分 0.10（0.10 × 0.45 = 0.045），不足以单独通过阈值，但能在其他维度分接近时起决定作用。

优化 4: 预建预设索引（性能）
问题: preset_bonus() 的部分匹配对每对骨骼线性扫描整个 preset_data 字典。设源骨架有 N 核心骨、目标骨架有 M 核心骨、预设共 P 条映射，则部分匹配的时间复杂度为 O(N × M × P)。50 个预设 × ~50 条映射 × 200×200 骨骼对 ≈ 1 亿次比较。

修改方案: 在 load_preset_mappings() 返回时额外构建两个索引字典，并缓存：

_preset_vg_index = None   # {vg_name_lower: total_count}
_preset_bone_index = None # {bone_name_lower: total_count}

def load_preset_mappings() -> tuple:

    global _preset_cache, _preset_vg_index, _preset_bone_index
    if _preset_cache is not None:
        return _preset_cache, _preset_vg_index, _preset_bone_index

    pair_counts = {}
    vg_index = {}
    bone_index = {}

    # ... 原有的文件扫描逻辑 ...

    for fname in os.listdir(preset_dir):
        # ... 原有解析逻辑 ...
        for vg_name, bone_name in paired_items:
            key = (vg_name.lower(), bone_name.lower())
            pair_counts[key] = pair_counts.get(key, 0) + 1
            vg_index[vg_name.lower()] = vg_index.get(vg_name.lower(), 0) + 1
            bone_index[bone_name.lower()] = bone_index.get(bone_name.lower(), 0) + 1

    _preset_cache = pair_counts
    _preset_vg_index = vg_index
    _preset_bone_index = bone_index

def _invalidate_preset_cache():

preset_bonus() 修改:

def preset_bonus(src_name, tgt_name, preset_data, vg_index, bone_index, max_count):

    src_lower = src_name.lower()

性能提升: 部分匹配从 O(N × M × P) 降为 O(N × M)（精确匹配是 O(1) 查表）。

优化 5: 预计算骨骼路径和位置缓存（性能）
问题: _get_bone_path() 和 _get_bone_head_local() 在 auto_match_bones 的双重循环中被反复调用，同一骨骼的路径和位置每次都重新计算。复杂度 O(N × M × avg_depth)，大量冗余。

修改: 在 auto_match_bones() 入口预计算并缓存，评分函数内部直接使用缓存值：

def auto_match_bones(src_armature_obj, tgt_armature_obj, threshold=0.25):
    src_bones = [b for b in src_armature_obj.data.bones if is_core_bone(b.name)]
    tgt_bones = [b for b in tgt_armature_obj.data.bones if is_core_bone(b.name)]

    bbox_src = _compute_bbox(src_armature_obj)
    bbox_tgt = _compute_bbox(tgt_armature_obj)

    preset_data, vg_index, bone_index = load_preset_mappings()
    max_preset_count = max(preset_data.values()) if preset_data else 0

    # 预计算缓存
    src_paths = {b.name: _get_bone_path(b) for b in src_bones}
    tgt_paths = {b.name: _get_bone_path(b) for b in tgt_bones}
    src_positions = {b.name: _get_bone_head_local(b) for b in src_bones}
    tgt_positions = {b.name: _get_bone_head_local(b) for b in tgt_bones}

    # 内部缓存版评分函数
    def _cached_hierarchy_score(sb, tb):
        path_a = src_paths[sb.name]
        path_b = tgt_paths[tb.name]
        depth_a, depth_b = len(path_a), len(path_b)
        depth_sim = 1.0 - min(abs(depth_a - depth_b) * 0.2, 1.0)
        min_depth = min(depth_a, depth_b)
        if min_depth == 0:
            return depth_sim * 0.4
        total_weight = 0.0
        weighted_sum = 0.0
        for i in range(min_depth):
            weight = i + 1
            sim = name_score(path_a[i], path_b[i])
            weighted_sum += sim * weight
            total_weight += weight
        path_name_sim = weighted_sum / total_weight if total_weight > 0 else 0.0
        return path_name_sim * 0.6 + depth_sim * 0.4

    def _cached_spatial_score(sb, tb):
        pos_a = src_positions[sb.name]
        pos_b = tgt_positions[tb.name]
        norm_a = tuple((pos_a[i] - bbox_src[0][i]) / bbox_src[2] for i in range(3))
        norm_b = tuple((pos_b[i] - bbox_tgt[0][i]) / bbox_tgt[2] for i in range(3))
        dist = math.sqrt(sum((norm_a[i] - norm_b[i]) ** 2 for i in range(3)))
        base_sim = max(0.0, 1.0 - dist * 2.0)
        mirror_dist = math.sqrt(
            (norm_a[0] - (1.0 - norm_b[0])) ** 2
            + (norm_a[1] - norm_b[1]) ** 2
            + (norm_a[2] - norm_b[2]) ** 2
        )
        mirror_sim = max(0.0, 1.0 - mirror_dist * 2.0)
        return max(base_sim, mirror_sim * 0.6)

    # 评分矩阵
    scores = []
    for sb in src_bones:
        for tb in tgt_bones:
            ns = name_score(sb.name, tb.name)
            hs = _cached_hierarchy_score(sb, tb)
            ss = _cached_spatial_score(sb, tb)
            pb = preset_bonus(sb.name, tb.name, preset_data, vg_index, bone_index, max_preset_count)
            total = 0.30 * ns + 0.15 * hs + 0.10 * ss + 0.45 * pb
            scores.append((total, sb.name, tb.name))

    # ... 后续贪心匹配逻辑不变 ...

注意: hierarchy_score() / spatial_score() 保持原函数不变，作为可单独测试的纯实现；auto_match_bones() 内部只使用缓存版，避免在双重循环里重复递归和属性访问。

优化 6: 修复预设解析的脆弱性
问题: load_preset_mappings() 使用 zip(vg_matches, bone_matches) 配对，假设预设文件中 vg 和 bone 严格交替成对出现。如果预设文件有注释行、空行、或格式异常，会导致错位。

修改为按 item 块解析，并用 index backreference 确保 .vg 与 .bone 属于同一 item_sub_N，防止跨项贪婪匹配：

item_pattern = re.compile(
    r'item_sub_(\d+)\.vg\s*=\s*[\'"]([^\'"]+)[\'"]'
    r'.*?'
    r'item_sub_\1\.bone\s*=\s*[\'"]([^\'"]+)[\'"]',
    re.DOTALL
)

for fname in os.listdir(preset_dir):
    if not fname.endswith(".py"):
        continue
    filepath = os.path.join(preset_dir, fname)
    try:
        with open(filepath, "r", encoding="utf-8") as f:
            content = f.read()
    except Exception:
        continue

    for _, vg_name, bone_name in item_pattern.findall(content):
        key = (vg_name.lower(), bone_name.lower())
        pair_counts[key] = pair_counts.get(key, 0) + 1
        vg_index[vg_name.lower()] = vg_index.get(vg_name.lower(), 0) + 1
        bone_index[bone_name.lower()] = bone_index.get(bone_name.lower(), 0) + 1

注意: 预设文件实际格式中 vg 行与 bone 行之间可能存在 item_sub_N.name = '' 等其它赋值，re.DOTALL + .*? 允许跨越多行，但 \1 保证不会跳到下一个 item。
